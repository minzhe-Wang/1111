## 开场前准备（不计入汇报）

1. 保持电脑接电，启动MariaDB、Redis、Python8001、Java8080。浏览器打开员工端 http://127.0.0.1:8080/ 和管理端 http://127.0.0.1:8080/admin.html 。启动说明见README。
2. 员工 employee / OfficeDemo1，管理员 admin / OfficeDemo2。员工与管理员用两个不同浏览器，或普通窗口与无痕窗口，避免同源登录令牌互相覆盖。不要临场展示`.env`或模型密钥。
3. PPT预先进入放映；本讲稿留在手机或纸上。先练一次口述和切窗口，PPT目标4分30秒。
4. 准备本目录的“追问演示票据_A.png”，备用“追问演示票据_B.png”。图片明确标记演示样例，不是真实发票。先前已成功提交过A，则改用未使用的B；哈希去重会阻止同一票据反复报销，这属于正确行为。
5. 预先确认“海棠厅”等目录中有启用会议室；准备明天上午9:00–10:00的空闲时段。不要沿用已经过去的固定日期。可预先注册专用演示员工账号，让记录列表更清楚。
6. 模型测试会消耗少量API余额。现场只执行必要的2–3次调用；不要连点。网络或模型迟迟无结果时按文末备用步骤继续。

## PPT逐页讲稿（约4分30秒）

### 第1页：项目介绍（20秒，累计0:20）

各位老师好，我是王闽浙，项目是“智行政——AI智能行政办公平台”。它覆盖个人日程、会议室、出差、用车、请假和报销六类事项。我重点介绍业务规则如何统一执行，以及AI怎样通过图文输入、追问和确认帮助用户完成申请。

### 第2页：架构与中间件（45秒，累计1:05）

系统有员工、管理员和移动H5三个入口。Java Spring Boot提供统一入口、管理鉴权，并通过JDBC直接处理目录维护和统计；Python FastAPI负责业务规则和Agent。MariaDB保存业务、草稿和历史，Redis保存目录缓存、对话历史和当前待补字段。Java修改会议室后会通知Python清除缓存。DeepSeek负责提取意图和图片信息，最终的权限与业务校验由服务端执行。

### 第3页：业务规则（40秒，累计1:45）

我们以确认后的需求作为统一规则来源。个人日程允许重叠，而且仅本人可见；会议室检查人数和时段，用车选择车牌，不做人数校验。请假和出差分别检查同类冲突，跨类型只提醒管理员。报销使用精确金额和票据摘要去重，只处理申请与审批，不表示已经付款。撤回、取消和归档都保留操作历史。

### 第4页：Agent和权限（45秒，累计2:30）

Agent先把输入解析成结构化意图，再调用白名单中的业务技能。可执行范围包括查本人日程、按人数找会议室、生成六类申请草稿。信息不足会追问，完整后展示可编辑草稿；用户确认版本后，服务端重新校验再提交。AI没有审批、归档和代别人办理的权限。重复确认不会新增第二条记录，取消或过期草稿也不能直接执行。

### 第5页：多模态和多轮（45秒，累计3:15）

这次重点增强了图片之后的文字补充。例如上传缺少金额的打车票据，系统先问金额，再回复38.50元，仍保留上一轮事由、类别和原票据。这些字段和附件引用按用户存入Redis，服务端合并并检查完整性。明确开始新申请时不沿用上一笔内容。我们还修复了1人会议室被误当成“人数未知”的问题。

### 第6页：调试和测试（45秒，累计4:00）

验证分三层：13组隔离回归覆盖权限、冲突、票据和草稿；18项真实联调覆盖Java、数据库、缓存和模型；浏览器测试覆盖桌面、移动和失败恢复。另外单独用真实图片验证了先追问再补金额的流程。本机100次HTTP查询、10并发没有失败，P95是91.44毫秒。这只是三条业务记录条件下的本机结果，不代表大规模部署，也不包含模型生成耗时。

### 第7页：切换演示（30秒，累计4:30）

下面展示1人会议室查询、图文追问、草稿编辑确认，再切管理员审批，最后看冲突和历史。需求、代码、测试与材料都保存在GitHub。当前是单实例课程项目，移动端为H5，开发中使用AI辅助，我负责需求确认、实现、调试与验证。现在进入系统。

## 6分钟现场演示（照顺序执行）

### 4:30–5:10：说明身份与查询技能

打开员工工作台，指出六类事项和聊天入口。点击“新对话”或清空上下文按钮，输入：

> 请给1个人找会议室。

预期：直接显示容量满足的会议室，不再追问“多少人”。

说：“这是查询技能，人数1是有效值。这里只按人数匹配目录，并不等于已经预约，实际提交还要检查时段。”

### 5:10–6:40：图片输入与缺字段追问

选择本目录的一张未使用演示票据，输入：

> 开始一笔新报销，事由是客户拜访打车费，类别交通。票据金额没有填写，请向我询问金额。

预期：提示补充申报金额，不生成业务申请。接着输入：

> 金额是38.50元。

预期：出现报销草稿，事由与类别保留、金额正确、票据1张。

说：“第一轮资料不完整，所以系统没有猜金额。第二轮只补金额，原图片引用由服务器保留。此时只是草稿，还没有提交报销申请。”

若模型多问了一个字段，按页面提示补充即可；不要声称每次模型用词都固定。

### 6:40–7:30：编辑、保存与确认

在草稿中将标题改为“客户拜访交通费（答辩演示）”。先点击“保存修改”，再点击“确认提交”，在申请列表展示新记录及待审批状态。

说：“修改会增加草稿版本，未保存修改时不能确认。确认后服务端再检查权限、字段和票据，写入申请。相同草稿重复确认会返回同一记录，防止重复提交。”

不要为了证明幂等而创建一份新草稿；新草稿是新操作，票据去重会另行拦截。重复确认的并发证据可展示tests/acceptance_v13.py第07组。

### 7:30–8:20：管理员审批与历史

切到独立浏览器的管理员页，刷新待审批列表，按刚才标题找到报销申请，查看票据和金额，点击通过。回员工页刷新，展示状态变化与详情中的操作历史。

说：“AI只能协助填单，审批由管理员完成。审批通过是审批结果，不表示系统已经执行付款。历史记录保留申请与审批操作。”

### 8:20–9:40：资源冲突和取消

用普通表单选择一个启用会议室、明天9:00–10:00、2人并提交。管理员批准后，再尝试提交同会议室同一时段的另一条申请。

预期：提示资源冲突；不要换到两个首尾相接的时段，首尾相接本来就允许。

如果准备充分，在员工端取消第一条已通过预约并填“演示结束”，展示取消历史。强调必须在开始前取消，开始时间以服务器北京时间判断。

说：“聊天和表单最终走统一规则。资源冲突由数据库事务中的校验处理，不能靠换一个入口绕过。”

### 9:40–10:30：中间件证据与收束

有时间：在管理员页修改一个会议室容量，回员工端刷新目录，展示同步变更。保持容量合理并恢复原值。

时间不足：直接打开tests/v13-live-result.json，指出Java目录维护、缓存即时失效以及100次查询结果。不要临时打开数据库连接配置。

说：“Java维护与Python读取共享数据库，并同步失效本地和Redis缓存。核心流程演示完毕，欢迎老师提问。”

## 常见问题与简短回答

| 老师可能问 | 建议回答 |
|---|---|
| Agent和普通聊天有什么区别？ | 本项目把模型输出约束成结构化意图，再路由到有限业务技能；有任务状态、追问、草稿和确认执行流程。它是受控办公Agent，没有宣称通用自主规划。 |
| Skill在哪里？用了SKILL.md吗？ | 业务Skill是main.py里注册的Python函数及草稿处理分支，agent_tasks.py负责补字段。没有接入外部SKILL.md插件执行框架。开发时使用AI辅助工具与应用运行时技能是两回事。 |
| 多轮记忆怎么做？ | Redis按用户保存最近12条消息、30分钟有效；待补字段、识别摘要和附件引用独立保存。明确新任务时隔离旧内容，新对话清空上下文，已有草稿保留。 |
| 图片下一轮没再上传，为什么还能用？ | 首轮把原文件保存为有归属的附件，Redis保留附件引用和结构化字段，第二轮合并金额，不依赖模型重新记住二进制图片。 |
| 支持哪些多模态？ | 文字和图片。聊天每次一张图，报销表单支持1–3张。没有实现语音、视频理解，也不做发票真伪鉴定。 |
| 为什么不让AI直接操作数据库？ | 模型可能误解输入，必须经过用户核对确认；所有入口统一做身份、资源、时段和票据校验。AI不能获得管理员权限。 |
| 金额为什么不用float？ | 使用Decimal避免二进制浮点误差；展示或模型返回38.5与38.50数值等价，最终按两位小数处理。 |
| 幂等与冲突有什么区别？ | 幂等防同一次操作重试产生两条记录；冲突检查防不同申请抢同一资源。草稿编号/版本及Idempotency-Key负责前者，事务中的资源校验负责后者。 |
| Redis坏了怎么办？ | 目录回源数据库；对话上下文显示不可用提示，此时不要依赖跨轮补字段。用户仍可通过表单和审批继续办理。 |
| 模型网络失败怎么办？ | 页面保留输入和图片，可重试或改用表单，不把失败包装成识别成功。 |
| 为什么Java和Python并存？ | Java承担Web入口、管理鉴权、JDBC目录维护和统计，Python承接模型与业务编排。共享规则边界和数据库事务锁，Java更新目录后通知Python失效缓存。 |
| 缓存策略是什么？ | 目录本地缓存3秒、Redis60秒，数据修改后主动失效；失效失败的脏键回源。当前按单Python实例部署，未证明多实例广播能力。 |
| 性能数据可靠吗？ | 有JSON记录和源码摘要；10并发、100次HTTP查询、账号3条记录，本机P95 91.44ms。模型耗时另计，不能外推到生产环境。 |
| RSI、自主多Agent做了吗？ | 没有。本项目可展示的是提示词约束、上下文存取、受控Skill、手工增强、故障复现与回归测试。 |
| 你具体做了什么？ | 由我负责需求确认、架构和业务实现、AI接入、调试与测试，开发过程中使用AI辅助生成和修改代码；能解释关键实现和测试证据。 |

## 代码定位（需要时再打开）

- main.py：`class Intent`、`skills`、`normalize_intent`、`chat`、草稿确认接口及统一业务校验。
- agent_tasks.py：`merge_task`、`resolve_action`、`prepare_task`，负责状态合并和缺字段追问。
- cache.py：用户上下文、目录缓存、失效和故障处理。
- java-server/src/main/java/cn/zhixing/AdminController.java：Java直接JDBC维护、事务与失效通知。
- tests/acceptance_v13.py：13组关键边界回归；tests/agent_followup_live.py：真实跨轮图文验证。

## 现场备用步骤

- 模型失败或等待过长：说明“本次识别失败，输入与图片仍保留”，转普通报销表单填写同样事由、类别、38.50元并上传图片，继续提交和审批。真实图文能力用本次测试JSON解释，不把表单流程说成模型成功。
- 显示票据重复：改用尚未提交的备用样例，或展示已有该票据记录。这恰好说明原始文件去重生效；不删除历史或关闭校验。
- 预约冲突影响第一条申请：选另一个启用会议室或未来空闲时段，不修改业务校验。
- 超过10分30秒：停止扩展演示，进入问答。保留完整录屏与源码，答辩后按老师要求提交。老师最新要求PPT可作实习报告，不必另写重复报告。

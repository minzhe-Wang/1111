## 启动

需要 Python 3.11+、Java 21、Maven 3.9、MariaDB/MySQL、Redis。
复制 .env.example 为 .env，配置 DATABASE_URL、REDIS_URL、JWT_SECRET、DEEPSEEK_API_KEY。
Redis有密码时使用 redis://:密码@127.0.0.1:6379/0，特殊字符需要URL编码。不设置模型密钥仍可使用表单及审批。

先启动数据库与Redis，然后在项目根目录执行：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt
.venv/Scripts/python.exe -m uvicorn main:app --host 127.0.0.1 --port 8001
```

另一终端：

```powershell
cd java-server
mvn package
java -jar target/office-web-1.0.0.jar
```

员工端：http://127.0.0.1:8080/ ，管理端：http://127.0.0.1:8080/admin.html ，移动端：http://127.0.0.1:8080/mobile.html 。API文档：http://127.0.0.1:8001/docs 。
演示员工 employee / OfficeDemo1，管理员 admin / OfficeDemo2。公开注册只能创建员工。

## 规则与实现

私人日程允许重叠且仅本人可见；用车选择车牌，无人数校验；一级审批不修改申请字段；开始前取消已通过会议室/用车需要原因。同人出差和请假各自检查重叠，跨类型只提醒。
报销使用十进制金额与1至3张票据，原始文件SHA-256全平台去重。审批不代表付款；归档保留原审批结果。修改、取消、撤回保留操作历史。
草稿支持独立编号、编辑递增版本、确认版本检查、取消、10分钟过期与重新生成。普通表单必须发送 Idempotency-Key，相同内容重试返回原记录。
业务使用北京时间及半开区间，客户端时钟不决定取消、过期、归档结果。
Java用JDBC读取目录、统计及修改会议室，与Python共享数据库互斥行；修改成功后同步通知Python失效本地和Redis缓存。返回值区分数据已保存与缓存失效结果。
缓存为本地3秒、Redis60秒。失效失败的键回源数据库。模型不可用时保留表单、审批；上下文不可用明确提示。
临时票据每小时清理一次，仅删除超过24小时且无有效草稿或业务记录引用的文件；历史申请附件保留。
当前为单实例课程部署，数据库互斥行串行保护写入；本机测试不能代表多实例扩展能力。

## Agent、图文输入与追问

用户连续对话复测后的修复：常见日期日程查询、人数筛选和指定会议室时段占用查询由服务端直接查真实数据，显示“系统查询与校验”。支持今天/明天/后天及明确年月日；不明确的日期与时段会要求补充。占用包含待审批与已通过申请，只返回是否占用，不泄露他人的申请详情。查询空闲不构成预约承诺。

明确申请类型会建立新的填写任务；补充阶段锁定业务类型，模型误判其他类型时继续澄清。只说“明天去上海”不会擅自设定起止时刻；“1234”不会当作报销金额。新对话同时清空页面已选图片，已有待确认草稿保留。16组隔离回归及`tests/conversation-live-result.json`记录混合业务连续对话复测；识别仍有覆盖范围限制，不宣称理解所有表达。

Agent通过结构化JSON选择代码中注册的技能：查询本人日程、按人数查询会议室、生成办公事项草稿。这里的Skill是项目中的受控业务函数，不是外部SKILL.md插件框架；没有实现自主多Agent协作或RSI自修改代码。

Redis按用户保存最近12条对话，30分钟有效；另存当前未完成任务的字段、缺失字段、图片识别摘要及服务端附件引用。`agent_tasks.py`负责字段合并、完整性检查与任务切换。图片内容由模型提取，后续文字可补金额而无需重新上传；图片原文件保存在附件目录，Redis只保存引用与字段摘要。

明确“再开一笔”等新任务会清除待补字段，并停止向模型传入上一任务的历史，防止沿用旧票据。短金额回复即使被模型误标为新任务也按补充处理。1人是有效的会议室查询人数，未知人数才追问。当前聊天支持每次1张图片，普通报销表单支持1–3张。

模型只提取字段，服务端判断缺什么；未知值不靠编造补齐。草稿需要用户检查、编辑并确认，随后才进入业务提交；AI不能审批、归档或操作他人数据。模型失败时页面保留文字及图片，可重试或改用表单。识别结果仍需核对，不能等同于发票验真。

## 旧数据迁移

启动自动添加车牌目录、票据归属和摘要、提交幂等表，以及草稿版本与取消时间。旧车辆表和业务记录均保留，不把旧车名猜测成实际车牌。管理员在车辆维护中新增真实车牌后使用新版用车。
旧归档数据如果没有保存审批结果，显示“历史审批结果待核实”，不会伪造结论；对应票据保守禁止重复使用。
升级前备份数据库及 receipts 文件夹。新增表与字段可保留，回退代码不应删除历史数据。

## 验证

`python tests/acceptance_v13.py`：临时SQLite隔离回归，不调用付费模型；Redis可用时附加上下文检查。
`python tests/live_v13.py`：真实Java+MariaDB+Redis联调，创建v13_测试账号和验收资源、记录，并调用两次模型。
`node tests/ui_v13.cjs`：需要Node.js与Playwright，项目根目录执行；可用PLAYWRIGHT_EXECUTABLE指定Chromium。创建ui_账号并调用一次模型。
`python tests/agent_followup_live.py`：4次真实模型调用，验证1人查询、图片缺金额→文字补金额→保留原票据、新任务隔离；不确认或提交业务记录。
测试结果保存为 tests/v13-*-result.json。旧 test-result.json 等不是新版完成证据。具体覆盖与材料边界见 验收材料/V1.3实现与验收记录.md。
